### v0.2 关键决策（2026-09-18，与项目 Owner 确认）

1. **管理员人工核验**：验证码通过即建档登录，核验作为运营层面事后抽查；不改 24 表数据模型、不新增迁移、不偏离文档 §8 DDL。
2. **首次登录建档**：邮箱通道拿不到学籍信息，新用户在登录流程第三步补全（真实姓名/昵称/年级/专业）后建档；真实姓名仅核验用，接口与页面均不下发。
3. **验证码假通道**：开发期写 app 容器日志 + 接口回显 `dev_code`（`EMAIL_CODE_ECHO=true`，生产关闭）；验证码「先校验、登录/建档成功才销毁」，避免 need_profile 中间态吞码；重发冷却 60s。
4. **测试策略**：CI（无 Postgres/Redis）只跑内存替身的单元测试（FakeRedis/假用户对象）；DB/Redis 相关集成验证在 compose 容器环境内执行（本表 E2E 证据即由此产生）。

**结论：v0.2 全部完成 ✅，可进入 v0.3（个人库全链路）。**

### 容器内 E2E 证据（2026-09-19，真实 DeepSeek 模型）

- 登录 → 建学期「2026 秋」→ 建个人课程「计算机操作系统」→ 上传真实课件 markdown（操作系统·内存管理）→ **5.8s 解析完成**（3 chunk，章节树自动建成，向量写入 `chunks_personal`）。
- 提问「分页存储管理的基本原理是什么？」→ SSE 逐字返回，citations 命中 `per_d1_00001/00002`（章节/小节/上传者署名齐全），done: token_usage=1094, latency=7.6s。
- 反幻觉用例「量子计算中的叠加态原理是什么？」→ 回答正确声明「资料中未提及」，引用仅标注在课程实际内容的相关说明句上。
- `qa_logs` 落库 2 行（含 token_usage/latency_ms），`ai_quotas` 当日 used=2/30 扣减正确。
- 未登录 401、他人课程/文档 404、md5 重复上传去重，均符合契约。

### v0.3 关键决策（2026-09-19，与项目 Owner 确认）

1. **Embedding 采用本地模型方案**（Owner 在三方案中选定）：torch CPU 版单独经 pytorch.org 源安装控制体积，模型构建期预下载烘焙进镜像，运行时离线加载；`requirements-ml.txt` 与主依赖分离，CI/本地检查不安装重依赖，代码对 sentence_transformers 一律惰性导入。
2. **章节摘要粗召回暂不生成**：summary_vector_id 回填任务（LLM 批量摘要）留待后续版本，v0.3 粗召回按文档 §8.3 既定降级路径走全课程精排，演示规模下检索质量无感。
3. **Office→PDF 预览（preview_key）延后 v0.4**：与公共资源在线预览一并交付；v0.3 溯源走 chunk 级原文视图（锚点 + 高亮 + 页码），LibreOffice 镜像能力已就位。
4. **上传接口 chapter_id 仅作预留**：章节由 tree_builder 从文档结构自动构建（不改 24 表 DDL，Document 无 chapter_id 列），人工归位随 v0.4 审核流一起做。
5. **无尾斜杠兼容**：`POST /api/documents`、`GET /api/library` 同时注册 `""` 与 `"/"` 路由——nginx 反代下 FastAPI 的 307 补斜杠重定向会丢失 `:8080` 端口。

## 六、协作规则速查（文档 §19）

- **分支**：`main` 保护 + `feature/xxx` + PR（≥1 人 review，CI 绿才合）
- **Commit**：Conventional Commits（`feat:` / `fix:` / `refactor:` / `test:` / `docs:`）
- **DoD**：代码合入 main + 接口契约文档同步 + 单测通过 + Owner 在迭代评审演示

- **节奏**：每周一次站会，每两周一次迭代评审；任务粒度 ≤ 3 天；每个迭代预留 20% 缓冲

## 七、常用命令速查

```bash

docker compose -f deploy/docker-compose.yml down          # 保留数据
```
